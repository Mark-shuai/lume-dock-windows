# 0.12.9：全部应用材质与自定义图标

## 使用方法

“全部应用”由接近黑色的背景改为中性灰色渐变、细高光和柔和阴影；浅色主题采用银灰色，搜索与筛选的顶部间距更紧凑。它是网页绘制的磨砂风格，CSS 不会模糊窗口外的 Windows 桌面。

自定义图标有三个入口：

1. 在全部应用中右键应用图标，或悬停/键盘聚焦后点击左上角“⋯”。触屏常显该按钮。
2. 在程序坞上右键固定应用图标（“全部应用”和“设置”功能图标也支持）。回收站的右键仍保留清空功能。
3. 在设置的固定入口管理列表点击“图标”。

选择本地 PNG、JPG 或 ICO 后立即保存；点击“恢复默认”取消覆盖。修改未固定应用的图标不会自动固定，之后点星号固定时沿用。已识别为同一程序的别名共享图标，Dock、全部应用和独立设置窗口同步。操作不更改源文件、Windows 快捷方式本身或启动目标。

图片缩小后嵌入本地配置，原图片移动/删除后仍保留；配置导入/导出携带图片。可输入8MiB以内、边长1–4096px的PNG/JPG；ICO支持内嵌PNG及未压缩24/32位帧，其他ICO请先转PNG。保留比例、透明角与真实黑色像素，图片最长边128px，复杂图片进一步缩至96/64px以满足48KiB的单图数据URL限制。最多100组记录且JSON按UTF-16估算不超过1MiB，以先达到的限制为准；满时提示恢复部分默认图标。图标只在用户选择时读取和压缩，不增加后台轮询。

## 已完成的验证

环境：macOS arm64、Electron 44.8.0；Windows x64交叉构建。

- `LUME_TEST_POWERSHELL=... npm test`：76/76通过，包含图标别名、保存重启、两个窗口合并与重置、容量/格式/错误回滚、解码前尺寸检查及现有主进程/PowerShell算法测试。
- `npm run test:custom-icons`：使用真实主进程、preload与本地文件读取，模拟系统文件选择器返回路径；验证透明PNG、JPG、PNG内嵌ICO、传统24位ICO透明掩码与黑色中心、超大/损坏图片、中文/空格/&路径、取消不修改、未固定应用修改后固定、应用别名同步、刷新不覆盖、自定义图覆盖异步原生图、两个原生窗口同步恢复、设置窗口尺寸不变、移走原图片后重载、配置导入/导出及存储失败回滚。验证重复右键不重复打开、真实Esc关闭并恢复Dock高度，以及实际440px渲染视口无横向溢出。
- `npm run test:appearance`：实际图标资产、邻近放大、减少动态效果、禁用放大与长列表溢出检查；人工查看灰色完整列表和深/浅主题、图标对话框、窄窗口截图。
- `npm run test:launcher`、`test:dedup`、`test:library`：搜索、键盘、加载失败重试、程序去重、星号固定/取消、扫描只收录及长程序坞滚动。
- `npm run test:settings`、`test:material`、`test:regressions`：独立设置实时预览、图标尺寸增减、玻璃参数、底座连续渐变、透明边角与裁切。
- `npm run test:quit`：两个窗口退出、辅助进程清理，用户打开的外部程序保留。
- `npm run dist`：使用带升级修复补丁的构建入口生成Windows x64安装包；asar运行源与当前源文件逐字节比对，架构与SHA-256见 `artifact-verification-0.12.9.json`。两个ZIP另带SHA-256，解压CRC和源文件核对通过。

测试中的列表、身份与原生图标结果为模拟数据。当前环境不能证明Windows原生文件选择器、安装/升级、桌面合成效果或长期内存占用正常；也没有配置代码签名证书。这次新增数据有上限，但不能据此把上限视为整个应用的内存占用。

## Windows 11 检查

1. 运行0.12.9安装程序，选择原安装路径，保留原有配置；无需清除注册表。
2. 深色/浅色主题、100%/125%/150%显示缩放下打开全部应用，确认中灰/银灰背景、搜索框和名称清晰；缩窄可用工作区后仍能滚动和搜索。
3. 在未固定的应用上更换透明PNG，确认未自动固定，之后固定到Dock图标沿用。打开设置列表恢复默认，检查两处同步。
4. 用JPG、ICO和中文路径图片试选；取消应保留旧图，错误文件应显示错误。移动原图、退出重启，图标仍保留。导出配置、恢复默认、重新导入，图片应恢复。
5. 从Dock直接右键编辑，Esc只关闭编辑框并恢复高度；设置窗口编辑时大小和位置不变。复查原来的星号、尺寸滑块和托盘退出/升级功能。
