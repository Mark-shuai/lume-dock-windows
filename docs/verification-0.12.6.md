# 0.12.6：全部应用按程序身份去重

## 使用变化

打开“全部应用”时，程序坞批量读取快捷方式实际启动的 EXE、参数、工作目录和 Windows 应用 ID。相同程序的桌面、开始菜单与系统注册入口合并展示，优先保留带真实图标的入口；搜索同时匹配原入口的名称。

合并后的星号匹配任一已固定别名，最近使用筛选也匹配原快捷方式。点击取消固定时，以一次持久化操作取消该程序的等价固定项；保存失败则保留原固定项与星号。再次固定时添加选中代表入口，启动仍传递该入口原始 target，不拼接/执行解析出的参数。

只凭同名不再覆盖程序，32/64 位或不同安装路径、不同参数与工作目录会保守区分；Windows 明确给出相同应用 ID 时用于关联系统入口。无法解析的快捷方式保留，PDF 说明、网页和其他非 EXE 入口继续独立显示。不会通过去重删除桌面文件、卸载应用或清空收纳存档。原始应用库记录继续保留，便于参数改变或失效后重新判断。

升级后打开全部应用即可重新识别；若快捷方式刚更改，可点“刷新列表”。无需清空配置。

## 实现与资源边界

- `app-identities.js` / `scripts/app-identities.ps1`：只读解析已有目标，无磁盘全量搜索、不启动目标；COM 对象在 finally 释放。
- 查询串行、每批最多 512 个目标，每次最多处理 3000 个不同目标；最多缓存 4096 条，成功缓存 5 分钟，未解析缓存 30 秒；显式刷新重新解析，读取失败保留已有成功结果。
- `renderer/app-identity.js`：使用应用 ID/EXE 身份关联别名并合并展示，迭代查找避免大量别名导致递归栈溢出。图标数据沿用原有大小限制。
- 没有新增后台定时器或常驻辅助进程。窗口打开/刷新时查询；既有图标缓存、大列表虚拟化和关闭后 DOM 清理继续保留。
- `windows-apps.js`：开始菜单按实际路径收集，注册应用按 AppID 收集，不提前按名称丢弃不同程序。主进程 `list-apps` 将目录与本地应用库/固定/最近目标一起做身份查询。

## Windows 11 实机步骤

1. 运行 `npm run test:windows-icons`，会在临时目录建立真实快捷方式，验证 EXE 解析、不同图标同目标合并与不同参数区分，最后清理 fixture。
2. 为 PotPlayer 或 QQ 音乐建立桌面与开始菜单快捷方式，打开全部应用并刷新；确认同程序只显示一项，保留正确图标，两个名称均能搜索。
3. 在旧快捷方式已固定/最近使用时刷新，确认合并后的星号与筛选正确；反复取消/固定并重启。
4. 用不同版本/路径或不同启动参数的程序测试，确认不会因同名被误隐藏；说明文档与官网入口仍保留。
5. 将其中一个快捷方式改为不同目标，刷新后应分开；删除/损坏一个快捷方式也不应删除其他记录或桌面文件。

尚未经过 Windows 11 实机验证，不将 macOS 上注入的身份 fixture 当作 Windows COM 成功证据。
