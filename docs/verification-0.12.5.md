# 0.12.5：程序坞尺寸与独立设置窗口边界

## 修复

此前 `dock:set-layout` 与显示器变化共用边界刷新函数，每次滑块输入都会把设置窗口的 `getBounds()` 再交给 `setBounds()`。这让程序坞布局变化不必要地触碰另一个原生窗口，也会反复经过平台窗口边界换算。

现在布局更新只调整 Dock。独立设置窗口只由用户拖动/缩放；在创建时或显示器工作区变化时才执行屏幕边界校正，且显示器事件中的边界没有变化时不写入。打开设置期间 Dock 仍显示，关闭设置释放独立 renderer。

没有新增后台轮询、依赖或常驻窗口，不改变配置结构，升级保留已有配置与快捷方式副本。

## 验证

环境：macOS arm64，Electron 44.8.0。以下自动化已通过：

- `npm test`：56 项通过；尺寸 IPC 从 40px/40% 放大到 72px/80% 再缩回，原生 Dock 高度为 147→202→147，模拟 1920px 工作区宽度为 960→1272→960。
- `npm run test:settings`：真实 Electron 双窗口测试中，设置窗口先拖动，再通过其控件将图标增至 72px、减至 40px；检查 Dock 高度、CSS 图标尺寸和宽度边界，并断言设置窗口位置/大小不变、程序对该窗口 `setBounds` 调用次数为零。覆盖关闭/重开、状态同步、实时外观及用户手动缩放。
- `npm run test:library`：应用只收录、双向固定、长 Dock 横向滚动与 40/64/72px 图标裁切。
- `npm run test:features`：尺寸持久化、重置/导入、不同图标大小和窗口宽度、运行圆点与容量失败回滚。
- `npm run test:regressions`：多种窗口宽度的图标边界、透明边角和长 Dock 首尾滚动。

`library` 和 `features` 的错误注入日志为测试 fixture，进程正常退出且断言通过。

## Windows 11 实机检查

macOS 自动化和 Windows x64 交叉构建不能代替 Windows 原生窗口/DPI 验证。安装 0.12.5 后：

1. 打开设置，手动移动并缩放窗口，记住其大小与位置。
2. 将图标大小 64→72→40→64px，确认底部图标实际变大、变小，设置窗口不改变尺寸。
3. 将底座宽度 80%→40%→80%，确认长 Dock 两个方向都能改变宽度，设置窗口不变。宽度仍受原有屏幕边界及 600–1080px 底座限制；短 Dock 会随内容收拢。
4. 连续拖动滑块、关闭并重新打开设置、重启应用，检查偏好与窗口交互。
5. 在 100%/125%/150%/200% 缩放、改变分辨率或断开副屏后重查，确保设置可见且不持续增大。

安装包、asar 版本及文件校验结果见同目录 `artifact-verification-0.12.5.json`。
