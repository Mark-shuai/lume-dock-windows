# 0.12.11：自动隐藏快速唤出防抖

## 改动

旧逻辑中，Dock 原生窗口底部位于工作区底部上方8px，而工作区底边触发区只覆盖上下4px。两者之间存在未覆盖的空隙，底部任务栏的中间区域也未纳入停留范围。快速滑动后停在这些位置，会开始离开计时，可能出现“显示、收起、再次显示”。这能从旧代码及坐标回放确认，但不能据此确定用户Windows现场的全部成因。

新 `auto-hide.js` 将唤出和停留判定分开：

- 隐藏时仍使用主屏幕、Dock横向范围内的工作区底边或物理屏幕底边触发，不扩大为整个窗口区域。
- 显示后，从窗口顶部一直到主屏幕底部作为连续停留范围，包含窗口下方空隙与任务栏。上方和左右增加12px容差，避免轻微移动反复触发。
- 边缘唤出后，自动隐藏至少等待1秒；真正离开连续范围约700ms才收起。重新进入清除离开计时，全屏隐藏始终优先。
- 限制坐标必须位于主屏幕内，下方另一显示器上的鼠标不会被误当作主屏幕底边。
- 继续使用原来的150ms鼠标轮询，不增加定时器、进程或逐帧窗口动画。只有需要改变可见状态时才调用原生显隐；模式切换、展开面板和显示器工作区变化会清理旧计时。设置预览期间暂停，关闭后恢复。

应用/快捷方式分类、自定义图标、启动目标和原配置保留。

## 验证

环境：macOS arm64、Electron 44.8.0。屏幕轨迹以模拟坐标驱动，窗口显隐使用真实Electron API。

- 单元测试 `LUME_TEST_POWERSHELL=... npm test`：84/84通过。
- 新增纯逻辑测试：顶部、底部、侧边与自动隐藏任务栏的不同工作区，零/正/负坐标起点，连续空隙/任务栏停留、触发与停留范围分离、快速越界保护、回入清理计时和重置过期状态。
- 主进程IPC回归：40/64/72px图标尺寸，快速进入工作区底边、下方空隙、任务栏、物理底边及图标区域，只发出一次显示请求；侧边抖动保留、真正离开会隐藏、最短显示时间、全屏优先和主屏幕下方坐标不误唤出；鼠标轮询最多一个。
- `npm run test:auto-hide`：真实原生窗口事件回放。先等待隐藏，快速进入底边再停在旧间隙1.4秒，经过物理底边到窗口内部，确认恰好一次原生show、没有中途hide；慢速路径也正常。检查离开收起、关闭自动隐藏立即显示、独立设置期间保持显示及关闭后恢复。
- `npm run test:settings`：独立设置、尺寸调整、自动隐藏暂停/恢复、配置同步与重载。
- `npm run test:categories`：应用/快捷方式隔离、搜索、固定/取消、图标入口、最近使用、键盘、重载与440px深浅主题。
- `npm run test:quit`：app/IPC两个退出入口销毁窗口、清理辅助进程，并保留用户打开的其他程序。
- 使用 `npm run dist` 构建Windows x64；asar源文件逐字节核对、版本、PE架构与SHA-256见 `artifact-verification-0.12.11.json`。源码和免安装ZIP另有SHA-256，校验CRC及内容与源文件一致。

没有在Windows实机移动鼠标测试，无法保证覆盖Windows任务栏动画、第三方任务栏工具或桌面合成引起的全部闪动。没有配置代码签名证书。

## Windows 11 验收

1. 托盘退出旧版，运行0.12.11安装包，选择原路径，保留配置；无需清注册表。
2. 开启自动隐藏，等待收起。快速将鼠标从屏幕中间滑到底部，分别停在底边、Dock下方空隙或任务栏上，再移到图标，观察是否只出现一次。
3. 连续快速滑入/移出，唤出后自动隐藏至少保留1秒，离开后正常收起，不应永远不收起；慢速移动仍正常。
4. 分别测试任务栏放顶部、底部，Windows缩放100%/125%/150%，图标40/64/72px；有多个屏幕时，在主屏幕下方的屏幕移动不应误唤出。
5. 打开设置调整尺寸时Dock保持显示；关闭设置恢复自动隐藏。全屏应用保持隐藏，显式通过托盘或快捷键唤出仍沿用现有策略。
