# 0.12.4：扫描应用库、双向星号与程序坞溢出

## 使用变化

- 启动时自动扫描，以及设置中的“重新扫描桌面”，都只把快捷方式收录到“全部应用”，不再自动塞进 Dock。“全部应用”的“刷新列表”也会重新扫描桌面。
- 点击应用旁的 ☆ 固定到 Dock；再点击 ★ 取消固定。取消固定只改变 Dock 列表，应用仍留在全部应用中，也不会卸载程序或删除快捷方式。
- 在“已固定”筛选中取消固定，该结果会从当前筛选消失；回到“全部应用”仍能搜索、启动或再次固定。普通列表固定/取消时保留滚动位置。
- 默认七个内置入口继续保留。旧版使用 `desktop-*` ID 记录的自动扫描入口，会在启动时迁移到应用库。明确固定的 `pinned-*`、手动添加的入口、右键收纳的存档以及分隔线不参与迁移。保存失败时回滚原列表，下次启动再尝试，不删除桌面文件。
- 固定项过多时，滚动视口位于玻璃底座左右边界内。显示左右按钮；普通鼠标滚轮转为横向滚动，触控板水平手势沿用原生滚动；按 Tab 聚焦入口会把图标滚动到可见区域，并预留放大空间。两端按钮到达边界时禁用。系统“减少动态效果”下按钮滚动立即完成。

## 数据与资源

`lume-dock-items-v1` 继续保存固定入口，`lume-dock-library-v1` 单独保存已收录入口。应用库与独立设置窗口沿用 storage 事件同步；配置导出包含 libraryItems，导入时去重合并，兼容旧配置没有该字段的情况。系统注册应用仍由原有的主进程目录读取，应用库补充桌面和取消固定的入口。

固定入口/分隔线仍最多 500 个，已收录入口最多 2000 个，两者不混用限额。应用库仅保存列表，不新增后台扫描定时器，未展开的启动台不创建应用网格；原有图标队列、缓存和大列表虚拟化继续使用。

滚动检测基于图标原始尺寸、间距和边距，不使用放大后的 scrollWidth。底座宽度显式固定到未放大内容的理想宽度，再由原生窗口限制；溢出时不会因滚动视口加边距而反复切换裁切。ResizeObserver 的布局更新在动画帧中执行，避免递归通知。长列表底座不再随边缘图标放大到窗口外。

## 验证

环境：macOS arm64、Electron 44.8.0、Node.js 24.14.0。Windows x64 安装包通过 electron-builder 构建；这不等同于 Windows 11 实机运行验证。

- `npm test`：56 项，包括应用库与固定列表分别限额、无效链接过滤、并发增删合并、收纳存档优先，以及已有 Windows 主进程测试。
- `npm run test:library`：模拟扫描 80 个桌面入口及重复路径，验证只收录不固定、星号双向切换、保存失败回滚、取消后重启/搜索/再次固定、已固定筛选、手动入口取消后保留、旧扫描项迁移、浮动设置同步、导出以及长列表按钮/滚轮/键盘在 40/64/72px 下的玻璃内裁切。
- `npm run test:launcher`：搜索、中文输入法、已固定/最近使用筛选、星号反复切换、启动失败、刷新重试和键盘导航。
- `test:ui`、`test:integration`：更新了扫描只进应用库的断言；右键主动收纳仍固定存档，先保存再确认回收桌面原件，失败时保留原件。
- `test:features`、`test:appearance`、`test:regressions`：不同尺寸/宽度的原生窗口边缘、放大/减少动态效果、透明边角、滚动首尾和分隔线回归。
- `test:settings`、`test:stability`：独立设置、实时预览、关闭释放与千应用/40轮开关的内存回归。

键盘聚焦裁切测试使用 Chromium 焦点模拟，避免后台测试进程受 macOS 前台应用影响。截图 `dock-overflow-0.12.4.png` 来自真实 Electron 渲染，背景透明在预览中显示为黑色。

## Windows 11 实机检查

1. 新建配置启动，桌面应用应出现在“全部应用”，Dock 仅显示默认入口。
2. 搜索桌面应用，连续点击星号固定/取消，关闭并重启，检查状态与搜索仍可用。
3. 升级旧配置，检查只有旧自动扫描项移到全部应用，手动固定项及右键收纳入口保留。
4. 固定很多应用，分别用鼠标滚轮、左右按钮和 Tab 查看最左/最右项；在 100%/125%/150%/200% Windows 缩放下检查没有图标露出底座。
5. 修改图标大小/底座宽度与减少动态效果，确认滚动与端点按钮正常；减少固定项后，左右按钮应自动隐藏。
6. 桌面右键主动选择“加入 Lume Dock”仍会固定入口；默认自动扫描不执行回收操作。
