# Windows 11 实机检查：0.12.14

## 第一步：自动检查开发版

1. 将完整 Windows开发包 解压到本地可写目录，安装 Node.js（建议22或更高版本）。
2. 从托盘退出日常使用的 Lume Dock，避免全局快捷键和窗口焦点相互影响。
3. 双击 `Windows实机检查.cmd`。首次自动执行 `npm ci` 安装开发依赖，需要网络。检查默认执行100轮交互，然后保持运行60分钟，每30秒采样。需要短检查时在该目录终端执行 `npm run verify:windows -- --quick`。
4. 检查结束后打开 `reports/windows-日期时间/summary.json`：`status` 应为 `passed`。若失败，请把此目录完整压缩给开发者；窗口提前关闭或超时也会记录失败。

等价命令：

```powershell
npm ci
npm run verify:windows
# 不等待一小时，但保留原生和交互回归
npm run verify:windows -- --quick
# 更长观察：120分钟，200轮交互，60秒采样一次
npm run verify:windows -- --minutes 120 --cycles 200 --interval 60
```

这些测试使用独立临时配置，不改日常固定项和设置，不启动清单中的个人应用。会读取本机开始菜单/应用注册数据，在系统临时目录创建少量测试快捷方式，读取/解码图标并清理测试文件；退出测试会终止其自己的辅助进程。开发模式不会注册右键收纳菜单。测试日志可能含本机错误路径，分享前可查看。长测不会自动让电脑睡眠、锁屏或操作真实安装器。

## 自动检查覆盖

- 单元、原生图标/透明边角、应用身份去重、性能与短时稳定性回归。
- AppsFolder真实图标按需读取、缺失应用降级；清单不含整批PNG。
- 程序退出时两窗口关闭、辅助进程结束，由程序打开的外部进程保留；升级脚本仅运行fixture逻辑，不安装/卸载日常应用。
- 独立开发窗口执行100轮打开、搜索、关闭；原生模式读取本机应用清单和Windows图标。每个阶段保存Electron进程CPU/工作集、渲染器JS堆，以及包含PowerShell辅助进程的Windows进程树工作集/私有内存/累计CPU时间。
- 图标辅助进程空闲后应退出；结束前重新打开，检查读取流程仍可继续。
- 锁屏、解锁、休眠、唤醒事件只记录发生时间，不主动触发，不代表通过兼容性验证。

内存单位：Electron工作集为KiB，Windows进程树工作集/私有内存与JS堆为字节。工作集包含共享页，不能直接求和当作独占内存。此采样器每次临时启动一个PowerShell读取进程状态，采样器自身不列入测试进程树，但采样会产生少量CPU扰动。长测不强制GC，保留正常回收行为；短时稳定性测试另测GC后的堆。`passed` 表示断言和流程通过，不自动证明CPU低于某阈值或长期无泄漏。

报告：`summary.json`记录套件及通过/失败状态，`soak.json`记录阶段采样，其他`.log`保留对应输出。保留`mode`、`platform`及`limitations`字段，避免把模拟报告当作Windows实测。

## 第二步：安装版手动检查

1. 先导出日常配置作备份，从托盘退出旧版，再运行 `dist/Lume-Dock-Setup-0.12.14-x64.exe` 原目录升级；不清理注册表。
2. 打开全部应用，检查第一屏、向下滚动、新搜索结果的真实图标；快速开关、刷新、取消固定和更换自定义图标。失效程序可以使用默认图标。
3. 验证桌面收录、应用/快捷方式分类、缩写搜索、自动隐藏、独立设置与尺寸预览。
4. 打开设置后托盘退出，任务管理器检查本应用及其辅助进程结束；重开确认配置保留。
5. 锁屏/解锁、休眠/唤醒后检查自动隐藏、全屏恢复、图标和设置同步。再做正常空闲一小时观察，记录持续增长或周期峰值，不单凭一次数字下结论。

目前开发机是macOS；上述Windows原生自动套件与安装步骤需要用户在Windows 11执行，未在开发机伪造通过结果。若第一步失败，先发送 reports 目录；若只有第二步出错，注明操作顺序及Windows缩放比例。
