# Lume Dock

Lume Dock 是一个面向 **Windows 11 x64** 的 Electron 桌面程序坞。启动时扫描桌面快捷方式并收录到“全部应用”，由用户点星号选择固定；也支持手动添加程序、文件夹和网址。

## 在 Windows 11 上继续开发

### 环境要求

- Windows 11 x64（Windows 10 未做完整验证）
- [Node.js](https://nodejs.org/) 20 或更高版本，建议使用 LTS
- npm（随 Node.js 一起安装）
- Git（如果要继续使用版本管理）

PowerShell 和 Windows Explorer 是系统自带依赖。应用读取 Windows 开始菜单时会调用系统 PowerShell；不需要另外安装 Electron 或 electron-builder。

### 获取项目并安装依赖

把整个 `Windows程序坞` 文件夹复制到 Windows 电脑后，在 PowerShell 中进入项目目录：

```powershell
cd "D:\你的目录\Windows程序坞"
npm ci
```

`npm ci` 会按照 `package-lock.json` 安装与当前项目一致的依赖。首次安装需要网络；如果之前没有安装依赖，不要直接删除 `package-lock.json`。

### 启动开发版

```powershell
npm start
# 或
npm run dev
```

开发版可用于修改界面、程序坞行为、全部应用搜索和桌面扫描。修改 JavaScript/CSS 后重启 Electron 即可看到结果。

开发模式不会注册 Windows 右键“加入 Lume Dock”菜单，因为右键菜单必须指向已打包的 Windows 可执行文件。需要验证右键收纳时，请先打包并安装 NSIS 安装包。

## 打包与安装

```powershell
npm run dist
```

该命令通过 scripts/build-windows.cjs 保留 electron-builder 的默认安装/卸载生成流程，并在构建进程内替换旧版卸载调用；不要绕过这个命令直接执行 electron-builder，否则会漏掉跨盘升级修复。上游模板变化时补丁会拒绝构建，需重新审查后适配。不会修改 node_modules。

成功后安装包位于：

```text
dist\Lume-Dock-Setup-0.12.9-x64.exe
```

双击安装包，在向导中选择安装目录即可。构建目标是 Windows x64，安装程序会创建桌面快捷方式和开始菜单快捷方式。当前没有配置代码签名证书，Windows 可能显示“未知发布者”提示。

`dist/` 和 `node_modules/` 已写入 `.gitignore`，复制源码或提交版本库时不会依赖这些生成文件。

### 旧版升级、退出或安装到 E: / D: 盘时报错

先取消并关闭旧的安装窗口，再运行 **0.12.9** 安装程序，选择原安装路径。安装前会请求该目录的旧版退出，并只清理准确匹配该路径的应用进程及已识别的辅助进程；不会全局按软件名称终止进程。旧卸载器丢失时继续修复安装，无需清除注册表。升级会在旧安装目录所在卷创建独立临时目录，将旧卸载器复制并校验后运行；只有它的子进程使用该临时目录，不更改系统 TEMP/TMP。旧版卸载失败会停止安装并保留恢复文件，日志写入 `%LOCALAPPDATA%\Lume Dock\InstallerLogs`。用户配置和收纳快捷方式副本仍保留在 `%APPDATA%\lume-dock`。

同时提供免安装运行包：解压到一个新文件夹，运行其中的 `Lume Dock.exe`。它可绕过旧版安装器，但不会替你卸载旧版或自动创建开始菜单入口；保持该文件夹路径不变，并且每次只运行一个版本。

退出不会删除卸载注册信息，也不会关闭已启用的桌面右键菜单。要移除右键菜单，请关闭设置中的对应开关；卸载时也会移除该菜单。若退出清理超时，会尝试在 `%APPDATA%\lume-dock\shutdown-last.json` 记录未结束辅助进程的 PID，供排查。

## Windows 系统托盘验证

安装并启动之后，Windows 任务栏通知区域会出现 Lume Dock 图标。右键图标可以：

- 打开或显示程序坞；
- 打开设置面板；
- 开关自动隐藏；
- 退出 Lume Dock。

托盘里的“自动隐藏”复选状态会和设置面板同步。托盘只在 Windows 上创建，macOS/Linux 开发环境不会显示该图标；因此需要在 Windows 11 实机上检查通知区域图标、菜单点击和退出行为。

## Windows 右键收纳实机验证

1. 运行安装后的 Lume Dock。
2. 打开设置，开启“桌面右键收纳”。该开关默认关闭，不需要管理员权限。
3. 在桌面上找到一个 `.lnk` 或 `.url` 快捷方式。
4. 右键该快捷方式，选择 **显示更多选项 → 加入 Lume Dock**。
5. 确认程序坞出现新入口，并且启动目标和图标正确。
6. 保存成功后，原桌面快捷方式会被移入回收站；程序本体不会被删除。

右键收纳支持个人桌面（包括 OneDrive 重定向）和公共桌面，只处理桌面根目录中的 `.lnk`、`.url` 文件。菜单调用时如果 Lume Dock 尚未运行，Windows 会先启动它；已运行时会把请求转发给现有实例。

如果程序坞保存失败、快捷方式内容在操作期间发生变化、权限不足或副本校验失败，桌面原文件会保留。可以从回收站恢复原件。关闭开关只会移除右键菜单，已收纳的入口和备份仍会保留。

## 主要功能

- macOS 风格磨砂程序坞、苹果风格“全部应用”按钮、悬停放大和邻近图标让位动效。
- 自动扫描个人桌面和公共桌面的快捷方式，只收录到全部应用；支持重新扫描，点击星号后固定。
- 设置中手动添加程序、快捷方式、文件夹和网址。
- “全部应用”读取 Windows 已注册应用和个人/公共开始菜单快捷方式。
- 应用名称搜索、已固定筛选、刷新列表、Enter 启动和方向键导航；星号支持固定和取消固定。
- Windows 原生图标读取；读取失败时使用通用图标。
- 自定义应用图标（PNG/JPG/ICO）、恢复默认；同步到 Dock、全部应用、设置列表，可导入/导出。
- 自动隐藏、登录 Windows 后启动、放大效果开关。
- 运行中应用圆点标记和主显示器全屏自动隐藏，均默认开启，可单独关闭。
- 分隔线分组；图标 40–72px、底座宽度 40%–100% 调节；六组预设及自定义强调色。
- Windows 系统托盘菜单：打开 Dock、打开设置、切换自动隐藏和退出程序。
- 系统信息区：显示当前时间；Windows 笔记本显示电池电量和充电状态，可点击音频入口打开系统声音设置。
- 设置中可开启系统信息栏；该功能默认关闭，适合使用 Windows 自带任务栏的布局。没有电池或系统接口不可用时会自动隐藏对应信息。
- 可选状态栏歌词：默认关闭，可在设置中输入歌曲名、歌手和逐行歌词，按设定秒数轮播显示；歌词条可独立于系统信息栏显示。
- 外观主题支持浅色、深色和跟随 Windows 外观，并自动保存选择。
- 玻璃底座支持独立调节圆角、透明度、模糊、高光和阴影强度；拖动滑块会即时预览，并自动保存到本机。
- 可选的回收站入口；单击打开 Windows 回收站，右键后经过确认可以清空回收站。
- 桌面右键收纳开关；保存成功后才移入回收站。
- 支持把文件、文件夹、程序或快捷方式直接拖到程序坞添加；重复入口会自动跳过。
- 支持从设置导出和导入 JSON 配置，迁移固定入口、已收录应用、外观、歌词和其他偏好。
- 支持 `Ctrl + Alt + Space` 全局快捷键打开“全部应用”，并自动聚焦搜索框。
- 启动台提供“最近使用”筛选，记录最近打开的 20 个应用或入口。

### 运行中标记、全屏隐藏与尺寸

“显示运行中标记”默认开启。在 Windows 中以实际可执行文件路径匹配进程；`.lnk` 会先解析真实目标，解析缓存最多 512 条、5 分钟过期。每 12 秒刷新，成功启动应用后约 1.5 秒额外刷新一次；隐藏窗口、打开设置或启动台时暂停轮询。进程查询串行、快照缓存 10 秒；失败清空标记并在后续刷新重试。网址、`.url`、系统协议和 UWP / Microsoft Store 入口不显示圆点；权限受限或启动器转交给其他可执行文件时也可能无法匹配。

“全屏时自动隐藏”默认开启。使用一个常驻 PowerShell 辅助进程，每 2 秒查询一次主显示器前台窗口：覆盖整屏、无标题栏，且不是普通最大化窗口、桌面、任务栏或 Dock 自身时隐藏。退出全屏后恢复；在全屏中通过托盘或全局快捷键主动唤出后，本次全屏期间保持可用。脚本文本通过 Electron 读取后编码传给 PowerShell，兼容安装包内的 app.asar 路径。关闭该设置会停止定时器并结束辅助进程。检测失败时保留上次状态，超时后清理并退避重试。边框特殊的窗口或独占全屏程序仍需实机验证。

在设置中点击“+ 分隔线”，拖动右侧管理列表调整位置，点击移除按钮删除。分隔线随配置保存与导入，不参与启动、搜索、最近使用或运行检测。固定入口与分隔线合计最多 500 个；达到上限时拒绝新增，右键收纳不会确认删除桌面原件。导入会去重合并，合并后最多保留 500 个。

图标大小范围 40–72px，默认 64px；宽度范围为主显示器工作区宽度的 40%–100%，默认 56%。底座目标宽度限制在 600–1080px，原生窗口还增加两侧各 96px 的放大留白，总宽度受可用工作区限制。小屏或入口较多时横向滚动，保留选择的图标尺寸。支持即时预览、自动保存和恢复默认尺寸。

强调色支持六组预设或自定义 `#RRGGBB`，用于交互选中及控件颜色，文字按颜色亮度选择黑色或白色。玻璃材质、主题、尺寸与强调色均可通过 JSON 配置迁移。

### 状态栏歌词

状态栏歌词默认关闭，不会改变现有 Dock 布局。打开“程序坞设置 → 显示状态栏歌词”后，点击“编辑歌词”输入歌曲名、歌手和歌词文本（每行一句），保存后歌词会显示在程序坞上方。开启“逐行播放”即可按 1–12 秒的间隔自动切换歌词，也可以关闭后只显示第一行。歌词设置保存在当前 Windows 用户的本地应用数据中。

当前版本使用手动歌词文本，Windows 的系统媒体会话不会提供统一的歌词内容接口；后续可以在此基础上接入具体播放器或歌词服务。

### 拖拽添加与配置迁移

将 Windows Explorer 中的文件、文件夹、`.lnk` 或 `.url` 快捷方式拖到程序坞底座，看到“释放以添加到程序坞”提示后松开即可。程序坞只保存入口路径，不会移动或删除原文件。设置面板中的“导出配置”会生成 JSON 文件；在另一台电脑打开“导入配置”即可合并固定入口并恢复外观、歌词和其他偏好。导入会跳过已存在的相同路径。

### 快捷键与最近使用

在 Windows 安装版中按 `Ctrl + Alt + Space` 可以从任意应用打开“全部应用”启动台，搜索框会自动获得焦点。每次成功启动应用后，启动台会记录最近使用的入口；切换到“最近使用”即可按最近启动顺序查看。快捷键由 Windows 全局注册，若被其他软件占用，程序坞会保持可用但该组合键不会生效。

Windows 没有覆盖所有磁盘中 `.exe` 文件的统一应用清单。本项目只读取系统注册应用和开始菜单，不做全盘扫描。绿色软件或没有开始菜单快捷方式的程序，请使用“手动添加”。

## 数据和配置位置

程序运行时通过 Electron 的 `app.getPath('userData')` 获取当前用户数据目录。Windows 通常是：

```text
%APPDATA%\lume-dock\
```

固定入口、设置、自动扫描去重记录和启动台数据目前保存在窗口的 `localStorage` 中。自定义图标另存于 `lume-dock-custom-icons-v1`：最多100组、图片最长边128px、单图PNG数据不超过48KiB，存储JSON按UTF-16估算不超过1MiB；不新增轮询。输入仅支持8MB以内、边长1–4096px的PNG/JPG或有效ICO。传统ICO支持未压缩24/32位与内嵌PNG，其他ICO请先转PNG。导出/导入JSON上限8,000,000字节。右键收纳的主进程数据位于：

```text
<userData>\desktop-integration.json
<userData>\Shortcuts\
```

`Shortcuts` 保存收纳后的快捷方式副本；桌面入口加入程序坞并确认保存成功后，原文件才会移入 Windows 回收站。卸载程序会移除右键菜单，但不会主动删除用户数据。

然后按改动范围运行测试：

## Windows 一键实机检查

开发包解压后双击根目录的 `Windows实机检查.cmd`，首次会安装依赖（需 Node.js 与网络）。默认读取本机程序清单和真实图标，执行100轮打开/搜索/关闭，再空闲采样60分钟；使用独立临时配置，不修改日常配置，不启动列表中的应用。报告保存在 `reports/windows-日期时间/`。

也可以在终端运行：

```powershell
npm ci
npm run verify:windows
# 先跑短检查：不等待60分钟，仍含100轮交互与原生回归
npm run verify:windows -- --quick
# 自定义时长、交互次数和采样间隔（秒）
npm run verify:windows -- --minutes 120 --cycles 200 --interval 60
```

它检查开发模式的原生接口和资源变化；真实安装、旧目录升级、托盘退出及睡眠唤醒需按 [Windows 实机步骤](docs/windows-validation-0.12.14.md) 继续检查。报告有 `passed/failed` 状态，失败时保留对应日志；短测通过不表示长期无泄漏。

## 已知限制

- 当前只停靠主显示器，尚未提供多显示器选择。
- 右键菜单、回收站、OneDrive 桌面、PowerShell 应用清单、Windows 原生图标和快捷方式启动需要 Windows 11 实机验证。
- 开发模式不会注册右键收纳菜单。
- 托盘菜单目前只在 Windows 上创建；托盘图标和菜单仍需 Windows 11 实机验证。
- 尚未实现代码签名。
- 运行标记和全屏检测依赖 Windows PowerShell；本机 macOS 模拟测试没有运行这些原生系统接口。
- 运行标记仅覆盖可解析为 exe 路径的入口；UWP、受限进程和特殊启动器可能不显示。全屏隐藏仅针对主显示器。
- 清空回收站需要 Windows PowerShell；取消确认或命令失败时不会删除任何文件。
- 便签和日历入口依赖 Windows 的 `ms-stickynotes:`、`ms-calendar:` 协议关联；没有对应应用时请手动替换入口。
- 终端默认入口依赖 `wt.exe`（Windows Terminal）。
- `renderer/assets/macos/sources.json` 记录了默认图标来源；这些图标属于原权利人，不包含在项目代码的 MIT 许可中。

## 稳定性与资源占用

目前针对长期常驻做了这些处理：

- 运行标记在窗口不可见或面板展开时停止轮询；全屏辅助进程关闭功能后销毁，异常时有超时与退避，不会每两秒启动一个新 PowerShell。
- 超过 120 个入口的启动台只创建可见行及附近的缓冲行，滚动和方向键仍可访问完整清单；关闭启动台后移除列表节点、释放应用索引和动态图标缓存，并停止排队的图标读取。应用清单由主进程缓存供下次打开读取。
- 应用索引在目录、固定入口、已收录列表或最近使用变化时重建；搜索和滚动复用合并、排序与标准化文本。Dock动画复用尺寸与计算数组，仅布局变化时重测，隐藏时取消动画帧。
- 原生图标请求由主进程合并，最多同时读取 4 个；主进程和启动台各自的动态图标缓存最多 256 条、按字符串估算不超过 4 MiB。应用清单不再携带整批原生图标；固定项中已保存的图片、自定义图标、解码图片、GPU 和 Electron 本身另外占用内存。
- 自动隐藏关闭或设置/启动台展开时停止鼠标位置轮询；系统信息关闭时停止时钟和电池定时器；窗口隐藏时暂停系统信息刷新和歌词轮播；由主进程显式发送可见状态，避免原生事件或网页可见状态延迟导致后台继续运行。
- 玻璃、主题、歌词和行为开关只保存设置字段；共享状态避免重复序列化同一份数据。Dock点击和右键使用固定的事件委托，重建图标时不逐项重新绑定。
- 启动和导入时校验数据类型、合并重复路径、整理最近使用记录，保留逐行歌词和数值 0；配置保存失败会提示，并在可行时回滚已经写入的字段，右键收纳不会确认删除桌面原件。
- 文件拖拽使用当前 Electron 的 `webUtils.getPathForFile` 接口；原生图标和入口打开失败可正常降级。

`npm run test:stability` 使用模拟的 1,000 个应用检查滚动、键盘跨行、异常配置、部分保存失败、窗口隐藏，以及预热后连续 40 轮启动台打开/搜索/关闭。它会生成 [docs/stability-report.json](docs/stability-report.json)，记录宿主系统、测试轮数、回收后的 JavaScript 堆和各进程工作集。报告中的堆内存只覆盖渲染进程 JavaScript，**不能当作整个软件的内存占用**；进程工作集包含共享内存，也不应直接相加当作独占内存。

随开发包提供的报告在 macOS 开发机上生成，属于短时间、模拟数据的回归检查。它无法证明 Windows 上长期运行没有泄漏，也无法预测目标电脑的实际占用。Electron 使用多个进程，存在固定内存开销；严格要求极小内存时，需要另行评估原生 Windows 技术方案。

在 Windows 11 安装版上建议补充以下实测：

1. 在任务管理器中观察 Lume Dock 整个进程组，分别记录启动后、空闲 10 分钟、反复打开启动台后和空闲 1 小时的内存与 CPU；检查是否持续上升。
2. 分别测试默认设置，以及系统信息、歌词和自动隐藏开启后的空闲占用；鼠标不操作时 CPU 应恢复空闲状态。
3. 连续打开/关闭启动台、搜索和设置至少 100 次，检查图标、最后一个应用、键盘移动、休眠唤醒和退出重启。
4. 验证 OneDrive 桌面、公共桌面、失效快捷方式和右键收纳；安装新应用后刷新清单。
5. 在目标 Windows 电脑运行 `npm run test:stability`，保留新报告。不要用任务管理器中单个渲染进程的数据代表整个软件。
